# 設計評論（Design Critique）

## 輸入（使用者會填，空白先問）
- 畫面：［Figma 連結 / 截圖 / 描述］
- 脈絡：這是什麼產品的什麼畫面、給誰用：［____］
- 階段：［早期探索 / 修整中 / 收尾拋光］
- 聚焦範圍（可選）：［例：只看導覽 / 只看行動版］

## Task
依序評五個維度，每個發現標嚴重度（🔴 嚴重 / 🟡 中等 / 🟢 小問題）：
1. **第一印象（2 秒測試）**：視線先落在哪？是設計者想要的嗎？畫面目的一眼看得懂嗎？
2. **易用性**：使用者能不能完成目標？互動元素夠明顯嗎？有沒有多餘步驟？
3. **視覺層級**：閱讀順序清楚嗎？該強調的有被強調嗎？留白和字級有在做事嗎？
4. **一致性**：間距、色彩、字型、元件行為前後一致嗎？（有設計系統就對照 [[design-system]]）
5. **無障礙快檢**：對比、觸控目標、字級。要深入就跑 [[a11y-check]]。

## 原則
- 講具體位置，不說「版面有點亂」這種空話——說「CTA 和導覽在搶視覺重量」。
- 每個問題附「為什麼」＋至少一個改法，不只挑毛病。
- 也要說做得好的地方（至少 2 點），不然只是找碴。
- 力度配合階段：早期探索看方向不摳細節，收尾才摳像素。

## Output
- 一句話總評（最大的機會點在哪）
- 依維度列發現：位置 / 嚴重度 / 問題 / 建議改法
- 做得好的 2–3 點
- 最優先改的 3 項（依影響排序）
