# UX 文案撰寫（UX Writing）

## Context
我在設計 ［產品名稱］，品牌語氣是 ［親切 / 專業 / 輕鬆 / 嚴謹］。使用者是 ［描述］。
要寫的情境：［____，沒指定就問］

（欄位 使用者會填。空白先問，不要腦補。）

## 情境公式
每種情境有固定結構，照公式寫就不會漏：
1. **錯誤訊息**：發生什麼 + 為什麼 + 怎麼辦。「付款失敗。銀行拒絕了這張卡，換一張或聯絡銀行。」——不寫「發生錯誤」。
2. **空狀態**：這是什麼 + 為什麼是空的 + 怎麼開始。第一次使用的空白頁是 onboarding 機會，不是死路。
3. **CTA 按鈕**：動詞開頭 + 具體結果。「開始免費試用」✅「送出」❌。按下去發生什麼，字面就要說清楚。
4. **確認對話框**：講具體動作和後果，不問「確定嗎？」。標題「刪除 3 個檔案？」+ 說明「刪了就救不回來」+ 按鈕「刪除檔案 / 保留檔案」（不用「確定 / 取消」）。
5. **載入狀態**：設定預期、降低焦慮。「正在整理你的資料，約 10 秒」比轉圈圈好。
6. **Tooltip**：短、有用、不講廢話（不解釋一眼就懂的東西）。
7. **Onboarding**：一次講一個概念，漸進揭露，不倒說明書。

## Task
為指定情境撰寫，每個情境提供 2 個版本（可一版安全、一版更有個性），並附一句「為什麼這樣寫」。

## 格式
標題（15 字以內）+ 說明文字（30 字以內）+ CTA 按鈕文字。tooltip / 載入等短情境只出一行字。

## 語氣對照
- 錯誤：有同理心、給出路，不怪使用者
- 成功：可以慶祝，但不要吵
- 警告：清楚、可行動
- 中性資訊：簡潔就好
