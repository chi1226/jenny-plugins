# 無障礙檢查（Accessibility）

## 輸入（使用者會填，空白先問）
- 畫面 / 設計描述或截圖：［____］
- 已知色彩/字級/元件規格（可選）：［____］

## Task
逐項檢查並標問題（通過/警告/失敗），每個問題附 WCAG 條文編號（求職作品或交付文件引用編號更專業）：
1. **色彩對比**（WCAG 1.4.3）：文字與背景達 4.5:1，大字（18pt+ 或 14pt 粗體）3:1。
2. **非文字對比**（WCAG 1.4.11）：icon、輸入框邊框、按鈕等 UI 元件對背景 ≥ 3:1。
3. **字級與可讀性**：最小字級、行高；放大到 200% 版面會不會壞（WCAG 1.4.4）。
4. **觸控目標**（WCAG 2.5.5）：按鈕/連結 ≥ 44×44pt。
5. **焦點與導覽**（WCAG 2.4.3 / 2.4.7）：Tab 順序合邏輯、焦點狀態看得見；所有互動元素鍵盤可達（2.1.1）。
6. **替代資訊**（WCAG 1.1.1 / 1.4.1）：圖片 alt、不能只靠顏色傳達資訊（色盲測試點）。
7. **狀態回饋**（WCAG 3.3.1 / 3.3.2）：錯誤有文字說明不只紅色、輸入框有 label 不只 placeholder。

## 常見地雷（優先掃）
對比不足、輸入框沒 label、只有 hover 沒 focus 樣式、彈窗焦點跑不出來、純色點狀態指示。

## Output
問題清單（位置 / WCAG 條文 / 等級 / 問題 / 修正）+ 最優先修的 3 項。
提醒：AI 檢查抓得到約七成，對比值和螢幕閱讀器行為最好再用工具實測（如 Stark、系統 VoiceOver）。
