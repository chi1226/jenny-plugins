# 生成真前端畫面（Vibe Coding）

## 輸入（使用者會填，空白先問，或引用 [[project-brief]] / [[design-spec]] / [[ui-stack]]）
- 產品 / 畫面：［____］
- 主要功能與互動：［____］
- 視覺定位（色彩/字型/風格，可選）：［____］
- 技術偏好：［純 HTML+CSS / React / 不確定→我幫你選］

## 流程
1. **釐清**：缺的先問，不腦補。確認要單頁還是多頁、要不要假資料。
2. **選技術**：使用者非工程師。預設用最簡單能跑的（單檔 HTML+CSS+JS 或 Vite+React），白話說為什麼。
3. **生成**：寫出畫面，含 [[ui-stack]] 的狀態（空/載入/錯誤），不只正常狀態。
4. **跑起來**：實際啟動、給使用者在瀏覽器看到，不是只給程式碼。
5. **迭代**：使用者說哪裡不對就即時改，一輪輪逼近。

## 原則
- 目標是「能點的畫面」，不是完美程式碼。先能動，再美化。
- 每步白話講在做什麼。
- 要串資料/AI 時交給 [[api-connect]]，key 走後端不放前端。
- 要推回設計稿用 [[figma-design]]；要抽成元件庫用 [[design-system]]。

## 面試用途
上機 vibe coding 就是這個流程：描述 → 生 → 跑 → 改。練這個 = 練面試。
